| ADR-016 | No public deployment or remote push in this handoff | User asked for design, planning and skeleton | Requested release/push action |
| ADR-017 | Freeze visual fixtures in a pure core module and expose them through a report surface | Renderer changes need a reproducible before-state; keeping fixtures outside React preserves the phenotype contract and save identities | FS-102/103 replace renderer or pattern semantics after measured comparison |
| ADR-018 | Anatomy v2 is a pure core geometry contract between phenotype and every renderer; renderer v2 draws it. Keep the v1 body Béziers, move anchors onto the measured outline, and limit eyes that cannot fit (with a listed adjustment) instead of letting them overhang | Attachment becomes testable without Canvas, a future PixiJS renderer can reuse the same anchors, and silhouettes do not drift. Lab records store no per-fish appearance version or archival portrait, so every lab fish re-renders under the current model; genomes, IDs and FS-101 signatures are unchanged | Per-fish expression versions and archival portraits (FS-404/FS-601), or a topology template (genome v2) that allows protruding eyes |
| ADR-019 | Development v2 derives marking anchors from phased two-locus haplotype blocks on the Pigments and Pattern chromosomes; the birth seed only jitters them; renderer v3 draws them in body coordinates | Existing v1 alleles and phase already carry inheritance, so markings travel with chromosome copies, recombine at real boundaries and move when a real locus mutates, without new loci or save fields. Measured sibling separation rose from 52% to 73% (FS-101 cohorts 51% to 82%). Lab fish re-render under the new model, as in ADR-018 | FS-105 human study fails; locus-specific founder distributions change chance sharing; genome v2 adds dedicated pattern loci |
| ADR-020 | Breeding goal, collection sort and favorites are device-local preferences under a separate validated key (`fishtank-sim.lab.v1.preferences`), not fields in world save v1 | Player annotations should not force a save-schema migration before FS-203. Missing or invalid preferences fall back to defaults and can never corrupt the world, unknown fish IDs are dropped, and a preserved unreadable world save also blocks preference writes | Import/export (FS-204) or IndexedDB persistence (FS-203) should carry annotations with the world, or favorites need to follow a world across devices |
| ADR-021 | Research surfaces (visual fixtures, selection experiment, resemblance study) generate their own seeded fish and never read or write the player's world. Study answers stay on the device until someone copies the record, and computational observers are always reported separately from people | Experiments stay reproducible and lineages untouched; nothing is transmitted without a deliberate action; exact measurements are not mistaken for human perception | A consented remote study service, or experiments that must run on a player's own lineage |
| ADR-022 | Replace the dense pedigree matrix with exact memoized ancestor-pair queries and an explicit stack; cap living fish at 480 and records at 10,000; paginate archive and child lists at 60 | Avoid world-sized allocation without changing pedigree F by imposing an ancestry cutoff. FS-112 ships with IndexedDB rather than assuming a localStorage quota | Pathological wide pedigrees or larger-scale worker benchmarks require further caching |
| ADR-023 | Runtime save schema v2 wraps unchanged world/genome v1; monotonic world-scoped command IDs, event IDs and integer ticks; compact replay into a checkpoint every 64 commands | Exact recent retries are no-ops; compacted retries reject as stale. Replaying the bounded journal must produce the stored world; old genetic identity and phase remain unchanged | FS-404 permanent life-history events or an authoritative server protocol |
| ADR-024 | IndexedDB current plus two valid snapshots rotate in one transaction; read-back verifies the write; compare-and-swap rejects stale writers; preserve raw legacy and unreadable records | Failed validation, quota or interruption must never silently replace a lineage. The FS-206 Web Locks lease now prevents proactive local races as well | Worker-owned persistence, incremental events, cross-browser failure matrix |
| ADR-025 | Proceed with the requested M2 foundation while recording M1's human resemblance gate as pending | User explicitly requested M1 and M2 development; automated appearance evidence does not substitute for people. FS-107 delivers an honest review, not a declaration that the milestone passed | FS-111 observer records become available |
| ADR-026 | Put high-frequency visual steering in a versioned module worker with transferable x/y/vx/vy frames; keep domain commands in the pure replay reducer | Motion load cannot block selection, React does not subscribe to coordinates, and a rendering worker failure cannot mutate fish identity/currency. One automatic restart precedes visible manual recovery | Biological scheduling or profiling justifies a broader worker-owned runtime protocol |
| ADR-027 | Advance every owned tank through one integer tick integrator; offline time uses normal 1×, clamps negative deltas and caps at eight hours | Visibility and motion speed must not change future biology. The contract can be tested before M3 state exists without inventing fake health/care effects | FS-301/302 add real integrated state or playtests change the protection window |
| ADR-028 | Use Web Locks for a proactive single-writer tab, with read-only secondary tabs and IndexedDB compare-and-swap fallback | Prevent two valid sessions from racing and give the user a clear takeover path while retaining safe behavior in browsers without Web Locks | Cross-browser support or collaborative/cloud worlds require another authority model |
| ADR-029 | Store anonymous FS-111 records in a validated in-repository pool and recompute scores from the frozen trial answers | Submitted score summaries are derived data; unique complete records and exact trial identity are the evidence. One record cannot pass the five-observer gate | Five records complete the gate, or a consented remote collection service replaces manual pooling |
| ADR-030 | Close FS-111 and M1's human-resemblance criterion on five anonymous observers of the fixed `study-v1-12x4` set; treat the unanimously missed markings trial (trial-9) as a follow-up, not a blocker | Every mode's Wilson 95% lower bound is above chance (full 76%, silhouette 84%, markings 53%), and 11 of 12 trials had a correct majority. Changing development v2 because of one misread trial without cue notes would be guesswork | A second seeded trial set or cue notes put markings at or near chance |
| ADR-031 | Checkpoint the idle persistent clock every five minutes instead of every 30 seconds; commands still autosave immediately | Every commit serializes and validates three snapshots on the main thread, about 1.3 s for a 10,000-record world, so 30-second clock saves would stall large worlds while idle. The saved tick and `savedAt` stay consistent, so reload catch-up is unchanged; at most five minutes of active time can count toward the eight-hour cap | Validation moves off the main thread or into incremental persistence, or M3 state needs finer checkpoints |
| ADR-032 | Genome v2 appends chromosome 9 (Color) and chromosome 10 (Ornament) instead of reinterpreting v1 loci. Stored genome v1 records stay unchanged and read as a classic baseline, every new birth is genome v2, and research surfaces pin genome v1 | The user asked for more appearance genes and chose to keep existing fish exactly as they are, with new features in about one founder in four. Separate derived random streams keep every v1 locus, mutation, fixture pin and FS-111 trial identical, while variety enters through unrelated stock and new mutations | Structural/behavior loci now need genome v3; revisit when per-fish appearance versions (FS-404/601) replace the baseline rule |
| ADR-033 | Ornament geometry is a pure core module in body-length units with abstract tones; the renderer resolves palettes and caches Path2D objects per phenotype and seed | Motifs, scales and fin patterns stay testable without Canvas (finite, bounded, deterministic), a later PixiJS renderer can reuse them, and each fish paints a few batched fills instead of hundreds of per-frame shapes | FS-701 profiling shows cache memory or fill cost limits |
| ADR-034 | Breed and buy commands carry an optional `genomeVersion`. The app sends the current version; an absent field replays the pre-FS-113 behavior (genome v1 children of genome v1 parents, genome v1 Newcomers) | Stored replay journals must reproduce their snapshots. Without this, every existing save with a recent breed or buy failed validation under genome v2 and opened in recovery mode | Journal compaction has retired every legacy command, or a later genome version changes birth outcomes again |
| ADR-035 | Model tank water as one well-mixed compartment per tank with explicit units (litres, mg/L dissolved oxygen, mg/L ammonia nitrogen, grams of food). It uses fixed half-game-hour steps aligned to absolute ticks, only basic arithmetic, and a flux ledger. Care time runs at one game day per 60 real seconds at 1×; motion speed never changes it | The GDD asks for a comprehensible one-compartment model. Fixed absolute steps make visible, background, offline and replayed intervals agree exactly, and avoiding transcendental functions keeps saved values identical across browsers. The ledger turns conservation into testable fixtures | Playtests change pacing, fish-level effects need finer steps, or profiling shows step cost matters |
| ADR-036 | World save v2 adds per-tank water, and world v1 migrates with default water. A runtime whose snapshot is world v1 validates its journal against the water-free projection, then starts water at that snapshot and folds the journal into a new checkpoint | Replaying a pre-water journal cannot reproduce water that never existed. Rebasing keeps exact retries stale (the revision is unchanged), and every later save validates its water through replay | A later world version adds other time-integrated state |
| ADR-037 | Life model v1 stores age, current length and a lagged condition per fish. Eggs hatch after 3 game days, and growth is logistic toward the genetic adult length, scaled by growth potential and condition. Condition comes from oxygen, ammonia and crowding; stages derive from length and age. Development runs once per absolute game day after water. Eggs cannot breed or be sold; hatched fish may still breed in the lab | The GDD separates current size from genetic potential and asks for bounded, directional, history-carrying effects. Day-boundary updates keep every time split and replay exact, and logistic growth gives a fry period with 18–30 day maturity at average growth | Feeding (FS-305), health (FS-305/307) or maturity checks (FS-401) change the inputs |
| ADR-038 | Any save from an older world version is validated against records only (identity, genome, pedigree, ownership and tanks) and rebased at its snapshot. Fish migrated from worlds v1–v2 become young adults at their adult length potential | Time-integrated state cannot be replayed under rules it predates. Lab fish were always drawn as adults, so adult stock keeps their appearance and sale quotes | A migration needs to reconstruct history instead of starting it at the snapshot |

| ADR-039 | FS-303 utility drives and pellet consumption remain transient worker state, protocol 2; persistent life/water still advance only through the shared clock | Visual playback and worker recovery must not feed fish or change saved biology; plant cover targets precede obstacle geometry | FS-305 introduces domain care commands |
| ADR-040 | Compound goals extend optional device-local preferences with up to three secondary traits; visible match, allele copy odds and pedigree F remain separate | One heuristic must not claim to predict offspring or conflate appearance and ancestry; old preferences load unchanged | Pair-level prediction and selection are implemented |
| ADR-041 | User-requested Genome 2 visual revision increments development to 4 and renderer to 5 while keeping genome 2 and classic v1 rendering | Calico previously dropped the second dot color; organic motifs and distinct scale textures can improve without changing inheritance. Existing v2 fish redraw under this visual revision | Per-fish visual model versions arrive in FS-404/601 |
| ADR-042 | Keep the breeding planner's options behind an accessible disclosure button; keep the desktop inspector sticky with its own viewport-bounded scroll area | The planner is information-dense and should give aquarium/collection content room when collapsed. A sticky inspector preserves selected-fish context while reviewing long collections without changing mobile flow | A future split-pane or mobile inspector redesign changes the layout contract |

| ADR-043 | 14 Sep 2026: behavior model 2 uses a snapshot spatial hash with stable candidate order, an ID map, and fixed normalized cover/rock presets shared with Canvas | Remove unconditional all-pairs work without changing utility ties; the saved planted flag already selects the habitat, and motion stays transient | Placement or morphology-aware collision requires richer footprints; dense clusters need further profiling |
| ADR-044 | 14 Sep 2026: deliver FS-403 early against immutable genomes, with 256 samples on a prediction-only seed namespace and exact pre-mutation genotype odds | Prediction does not depend on lifecycle state; makes M4 progress while care and nursery contracts remain open. Labels distinguish scores, percentiles and odds | Normal-mode integration, changed genome/mutation rules or measured preview cost requires revisiting prediction version 1 |

| ADR-045 | 14 Sep 2026: care model v1 (world v4) gives each tank one shared food pool. The feeder dispenses a multiple of the residents' current need, fish eat up to their need, and the fed share of each game day becomes the nutrition factor. Condition is the health measure, fish never die, and every factor in the environment is also listed as a limit | A per-fish hunger ledger would add state without a visible gain over a one-compartment tank. Need-based rations make Measured the balanced default for any stocking and give Light and Generous clear tradeoffs. Listing every factor means condition cannot fall without a named cause | Individual feeding competition, disease or challenge-mode mortality |
| ADR-046 | 14 Sep 2026: equipment tiers and water changes cost lab credits; food has no recurring cost; care warnings open a preview instead of applying a fix | At one game day per real minute, a food bill would dominate the bounded lab economy and could strand a player during protected absence. Previews run the same deterministic advance on a copy of the tank, so a shown effect equals the applied one | M5 economy adds upkeep with a starter reserve and no-money recovery |

| ADR-047 | 14 Sep 2026: stage appearance v1 derives a juvenile phenotype in pure core from saved life state (body maturity from length, pigment maturity from age), quantized to twentieths. The tank and "Now" portraits draw it; the adult phenotype stays the genetic potential and a labeled preview. Renderer v6 adds swim motion (tail sweep, fin flutter, eased turns, frame interpolation) that portraits never use. No save or genome change | Keeps development in core and the renderer a consumer, makes growth visible without a schema bump, and caches few phenotype objects per growing fish. Steering keeps adult movement traits so visual stage cannot alter behavior outcomes | Per-fish appearance versions (FS-404/601), stage-dependent behavior, or archival portraits |

| ADR-048 | 14 Sep 2026: the absence summary observes the ordinary protected catch-up through an optional per-day hook instead of re-simulating or storing history, and reports a count of condition declines without a named cause that must stay zero. Care scenarios run seeded worlds in Research, with the stressed tank tuned so decline builds over days and recovery follows the first review | Observing the same advance guarantees the summary describes exactly what was applied and cannot change the restored world. The zero count turns "no unexplained health decay" into a check rather than a claim. A tank that is already at zero oxygen by the first reading demonstrates a crash, not care that a player can read and correct | Clutch events join the summary (FS-402), challenge-mode mortality, or catch-up moves to a worker |

| ADR-049 | 14 Sep 2026: normal breeding (world v5) splits hard pairing rules (roles, adult stage, condition, rest, one courtship per fish and per nursery, a shared tank, free nursery places, population limits) from soft courtship pauses (separation, condition, harsh water). A pairing reserves its nursery places, and every arrival counts reservations. Courtship and spawning run at game-day boundaries; eggs are consecutive tracked fish dated from the pairing timestamp. The instant `breed` command stays, labeled as a research shortcut | Checking hard rules atomically and reserving before conception means a clutch can never overflow a tank or duplicate on reload. Recording pause reasons each day keeps delays understandable, as the GDD asks. Keeping `breed` preserves replay of existing journals and the lab's fast experiments without making them the default path | Natural breeding per tank, variable clutch sizes from fertility, or courtship behavior in the motion worker |

ADR-001–042 are dated 13 September 2026; later rows state their dates. They are implementation guidance, not user-approval gates. Future agents may resolve routine details within the user’s authorized scope and record evidence-driven changes here.
